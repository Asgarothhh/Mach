**Статус:** черновик для согласования (frontend/UI + speech)
**Версия:** 0.3 (заменяет 0.2)
**Дата:** 14 октября 2026 г.
**Роль-владелец:** Frontend/UI; озвучка — совместно со speech/ML
**Нормативный источник:** `docs/SPEC_MTS_VOICE_AGENT_TRACK1.md` (SSOT, v1.1) — §5.2 «Состояния сессии», §5.7 «Streaming TTS и playback», §8.1 «Клиентское приложение», §8.3, §9, §11.4, §12.5; NFR-01, NFR-03, NFR-10.
**Область:** визуализация маскота и эмоциональная директива для TTS.

**Изменения v0.2:** маскот зафиксирован как «куб с ртом»; атлас расширен с 8 до 14 эмоций; добавлен каталог движений для иммерсивности (включая lipsync); добавлен нормативный раздел об эмоциональной озвучке: лицо и голос обязаны управляться единым источником эмоции.

**Изменения v0.3:** снято противоречие с исключением клонирования голоса (§3, §9.5); MF-16 уточнён под плановую перезагрузку Chatterbox (§9.2); задан per-request контракт `exaggeration`/`cfg_weight` вместо изменения конфига адаптера (§9.2); единицы просодии, фолбэк без `rubberband` и внешние зависимости (§9.3, §9.5); числовые пороги приёмки голоса и тесты (§9.4, §12); стартовые значения «радости» и «удивления» смягчены (§9.3); выбор голоса и референса (§9.5). Новые требования нумеруются MF-30 и далее, существующие ID не меняются.

> Правило приоритетов: SSOT выше этого документа. Состав и названия состояний берутся из SSOT; при их изменении обновляется раздел 4. Эмоциональная директива TTS затрагивает контракт §5.7 и требует правки SSOT + ADR до реализации в backend (§9.2). Распознавание эмоций звонящего в границы этой версии не входит (§13).

## 1. Назначение и идея

Маскот — визуальный компаньон экрана разговора web-консоли (`ConversationPage`, `/voice/live`). Форма утверждена: **простой скруглённый куб с ртом**, без глаз и бровей. Рот — единственная лицевая деталь; эмоция передаётся формой рта, поведением корпуса (наклон, сжатие, подскок, вибрация), лёгким свечением и — синхронно — озвучкой агента.

Почему куб идеально покрывает B2B своей простотой:

1. **Универсальность.** Нет человеческого лица и культурно-зависимой мимики глаз/бровей — нет риска неверного прочтения; один силуэт понятен в любом языке и отрасли.
2. **Простота.** Один силуэт, одна лицевая деталь, один атлас эмоций; рендер — SVG + CSS, без анимационных библиотек и ассетов.
3. **Брендируемость.** Форма одна, корпус перекрашивается токеном `--mascot-body` под бренд тенанта (white-label) без изменения геометрии.
4. **Единый эмоциональный контур.** То же выражение, что показывает куб, задаёт просодию озвучки (§9): клиент никогда не слышит и не видит противоречивых сигналов.

```
SSOT §5.2 / §8.1 (enum состояний)
        │
        ▼
mascotExpressionForState(state) ──┬──► <MascotCube expression/>      (мимика + движение)
        ▲                         └──► TTS emotion directive          (просодия, §9)
        │  задел (extension, §5): внешний источник эмоций
        └── override {expression, intensity, ttlMs}
```

## 2. Термины

- **Выражение (expression)** — единица атласа (§6): «злость», «грусть», «радость» и т. д.
- **Интенсивность** — 0…1, масштаб проявления эмоции; по умолчанию 0.6.
- **Драйвер A** — маппинг состояний SSOT → выражение. Нормативен для MVP (§4).
- **Драйвер B** — внешний источник эмоций с ограниченным временем жизни. Задел (§5).
- **Эмоциональная директива** — `{label, intensity}`, передаваемая в TTS вместе с текстом (§9).
- **Атлас** — полный перечень допустимых выражений (14, §6).

## 3. Границы

Входит в эту спеку:

- куб-компонент, атлас 14 эмоций, драйвер A, движения и иммерсивность, lipsync;
- контракт эмоциональной директивы для TTS, таблица «эмоция → просодия», правила честной деградации адаптеров;
- доступность, приватность, тесты и приёмка.

Требует правки SSOT + ADR (эта спека фиксирует требование и интерфейс, не реализацию):

- поле эмоции в `TTSRequest` и в контрактах §5.7/§9;
- пер-запросное управление просодией (например, `exaggeration` Chatterbox);
- запись метки эмоции в `tts_events` (§8.3).

Не входит:

- распознавание эмоций звонящего (SER/sentiment) — отдельная спека + ADR;
- клонирование голоса реального человека и любые биометрические модели. Допускается только синтетический референсный клип, сгенерированный самим проектом из разрешённого голоса движка (§9.5, MF-38);
- изменения прочих backend-событий, БД, метрик;
- использование маскота в admin-панели.

## 4. Драйвер A — мимика от состояний SSOT

Принцип: одно активное состояние → ровно одно выражение. Источник — существующий `voice.state` (`VoiceState`, `apps/web/src/shared/types/voice.ts`) и производное демо-состояние `env.demoMode` (как сейчас в `ConversationPage`). Новые WS-события не требуются.

### 4.1. UI-состояния (§8.1) — нормативный маппинг MVP

| UI-состояние | Выражение | Куда попадает в MVP |
|---|---|---|
| `idle` | `neutral` | ожидание, парение |
| `requesting_microphone` | `curious` | куб наклоняется и «ждёт» |
| `connecting` | `thinking` | |
| `listening` | `attentive` | наклон вперёд, слушает |
| `processing` | `thinking` | поиск по источникам |
| `speaking` | `speaking` | рот синхронизирован с озвучкой (lipsync) |
| `degraded` | `sad` | голос недоступен, продолжение текстом |
| `ended` | `joyful` | тёплое завершение |

`chat_handoff` и `human_handoff` уже перечислены в §8.1, но пока не входят в TS-тип `VoiceState`; при их добавлении выражение — `neutral` (закреплено заранее).

### 4.2. Полный enum сессии (§5.2) — запас на будущие UI-состояния

| Состояние сессии | Выражение | Комментарий |
|---|---|---|
| `CREATED` | `neutral` | |
| `CONNECTING` | `thinking` | |
| `NOTICE_PENDING` | `attentive` | озвучивается уведомление о записи |
| `LISTENING`, `ENDPOINT_PENDING` | `attentive` | |
| `TRANSCRIBING_FINAL` | `thinking` | |
| `ROUTING`, `RETRIEVING`, `GENERATING` | `thinking` | визуально не различаются |
| `SPEAKING` | `speaking` | |
| `INTERRUPTED` | `surprised` | TTL 600–900 мс, затем снова `attentive` |
| `DEGRADED` | `sad` | |
| `CHAT_HANDOFF_PENDING`, `CHAT_HANDOFF` | `neutral` | |
| `HUMAN_TRANSFER_PENDING`, `HUMAN_HANDOFF`, `HANDOFF` | `neutral` | |
| `CLOSED` | `neutral` | |

`INTERRUPTED` пока не приходит во фронт (barge-in гасится на уровне TTS); строка закрепляет поведение на момент появления состояния в событиях.

### 4.3. Требования драйвера A

- **MF-01 MUST** — маппинг исчерпывающий: `Record<VoiceState, MascotExpression>`; новое состояние без выражения ломает сборку TypeScript.
- **MF-02 MUST** — лицо и рот не показывают содержание разговора, chain-of-thought, внутренние инструкции и подсказки промпта (SSOT §8.1).
- **MF-03 MUST** — demo и live используют один маппер; отдельной «демо-мимики» нет.
- **MF-04 SHOULD** — при неизвестном рантайм-значении используется `neutral` без исключения.

## 5. Драйвер B — внешние эмоции (задел)

### 5.1. Контракт

```ts
// apps/web/src/features/voice/components/MascotCube.tsx
export type MascotExpression =
  | 'neutral' | 'attentive' | 'curious' | 'thinking' | 'speaking'
  | 'joyful' | 'surprised' | 'confused' | 'skeptical' | 'empathetic'
  | 'sad' | 'apologetic' | 'relieved' | 'angry';

export interface MascotCubeProps {
  expression: MascotExpression;
  /** 0…1, по умолчанию 0.6 */
  intensity?: number;
}

// apps/web/src/features/voice/model/voiceExpression.ts
export function mascotExpressionForState(state: VoiceState): MascotExpression;
```

### 5.2. Приоритет и переходы

- Внешняя эмоция — `expressionOverride: { expression; intensity?; source; ttlMs }` — имеет приоритет над маппингом состояний и распространяется и на лицо, и на озвучку.
- **MF-05 MUST** — override всегда ограничен TTL; по истечении куб и голос возвращаются к выражению из состояния. Постоянной ручной фиксации нет.
- **MF-06 MUST** — источник override — только код приложения (модель голосового опыта); не URL, не `localStorage`, не `window`.
- Переход между выражениями — spring 180–260 мс (§8.4); при `prefers-reduced-motion` — мгновенная смена.

### 5.3. Источник реальных эмоций — вне границ

SER/sentiment по речи звонящего не входит ни в SSOT, ни в архитектуру §4; §2.6 ограничивает латентность 300–400 мс, а эмоция — потенциально чувствительный атрибут (§7 SSOT). Источник проектируется отдельной спекой + ADR; этот документ фиксирует только интерфейс отображения, чтобы UI и озвучка не переделывались.

## 6. Атлас эмоций (14)

Ровно 14 выражений; расширение — изменение этой спеки. «Достижимость»: **A** — драйвер A в MVP; **A·f** — драйвер A на будущих состояниях; **B** — только драйвер B после ADR.

| # | Выражение | Рот | Корпус и движение | Свечение | Достижимость |
|---|---|---|---|---|---|
| 1 | `neutral` — спокойствие | мягкая линия, уголки чуть вверх | парение ±3 px, цикл 4 с | базовое | A |
| 2 | `attentive` — внимание | собранный маленький рот, лёгкая улыбка | наклон вперёд 6°, scale 1.03 | базовое | A |
| 3 | `curious` — любопытство | небольшое «о» | наклон вбок 8°, подъём 4 px, покачивание | базовое | A |
| 4 | `thinking` — задумчивость | линия, один уголок вниз | медленный наклон 10° с покачиванием, цикл 3.5–4.5 с | базовое | A |
| 5 | `speaking` — речь | раскрытие по амплитуде озвучки (lipsync) | микро-подпрыгивание 1–3 px по слогам | базовое | A |
| 6 | `joyful` — радость | широкая дуга вверх | пружинистое покачивание, подскок 4–6 px | +10% яркости | A |
| 7 | `surprised` — удивление | большой круг «о» | прыжок 8–10 px, squash&stretch вверх | +10% яркости | A·f (`INTERRUPTED`) |
| 8 | `confused` — непонимание | волна «~» | наклон вбок ±6°, медленное покачивание | базовое | B |
| 9 | `skeptical` — сомнение | полуухмылка вбок | медленный наклон назад 4° и пауза | −5% яркости | B |
| 10 | `empathetic` — сочувствие | мягкая неглубокая дуга вниз | наклон вперёд 8°, замедление, мягкая тень | базовое | B |
| 11 | `sad` — грусть | глубокая дуга вниз | оседание: squash 6% вниз, затухание движения | −10% яркости | A (`degraded`) |
| 12 | `apologetic` — сожаление | дуга вниз с лёгкой волной | поклон вперёд 12° с короткой задержкой | базовое | B |
| 13 | `relieved` — облегчение | небольшая дуга вверх, «выдох» | плавный подъём 4 px и расслабленное опускание | тень светлеет | B |
| 14 | `angry` — злость | сжатая линия с опущенными краями | быстрая вибрация ±1.5°, насыщенность + | +15% яркости | B, policy-off |

- **MF-07 MUST** — в MVP драйвер A не выдаёт эмоции категории B (`confused`, `skeptical`, `empathetic`, `apologetic`, `relieved`, `angry`): для них нет состояний в SSOT. Придумывать триггеры запрещено.
- **MF-08 MUST** — `angry` по умолчанию не направлена клиенту (policy-off): допустима только в demo-предпросмотре и внутренних сценариях; включается политикой тенанта отдельным решением.
- **MF-09 MUST** — все 14 выражений воспроизводимы для визуальной приёмки через demo-предпросмотр (§5.1).

### 6.1. Покрытие B2B-сценариев

| Сервисная ситуация | Эмоция |
|---|---|
| Приветствие / уведомление | `attentive`, `neutral` |
| Слушание | `attentive` |
| Поиск ответа | `thinking` |
| Ответ голосом | `speaking` |
| Уточнение (низкая уверенность) | `confused` (B) |
| Проверка источника | `skeptical` (B) |
| Ограничение / извинение | `sad`, `apologetic` (B) |
| Перевод на человека | `neutral` |
| Завершение | `joyful` |

## 7. Компонент «куб»

- Файлы: `apps/web/src/features/voice/components/MascotCube.tsx`, маппер — `apps/web/src/features/voice/model/voiceExpression.ts`, стили — секция `/* Voice mascot cube */` в `apps/web/src/styles/global.css`.
- **MF-10 MUST** — новые npm-зависимости не добавляются: React + inline SVG + CSS; Lottie/Rive/Spine не вводятся.
- **MF-11 MUST** — компонент не делает сетевых вызовов, не читает/не пишет storage, не логирует.
- Анатомия: скруглённый куб (superellipse, viewBox 240×240), рот — единственная лицевая деталь; глаза и брови сознательно отсутствуют. Корпус — `--color-brand` (white-label через `--mascot-body`), рот — белый. Лёгкий 3D-объём: `perspective` + наклон `rotateX/rotateY` до 6°, тень смещается за наклоном.
- Размер: `clamp(112px, 20vw, 168px)`; на узких экранах куб не вытесняет заголовок и кнопки.
- Размещение (нормативно): `ConversationPage`, внутри `.voice-stage`, **вместо** `<Waveform variant="stage" />`; `Waveform` сохраняется на `HomePage` и `ConnectingPage`.

## 8. Движение и иммерсивность

### 8.1. Базовые движения

| Что | Параметры | Когда |
|---|---|---|
| Парение | ±3 px, цикл 4 с | `neutral` и все паузы |
| Дыхание | squash ≤ 1.5%, цикл 4 с | `attentive` |
| Микро-покачивание | ±1.5°, цикл 5 с | постоянно, кроме `sad`/`angry` |
| Тень | следует за наклоном/подскоком, мягкая | постоянно |

### 8.2. Lipsync (озвучка → рот)

- **MF-12 MUST** — при воспроизведении ответа раскрытие рта следует за реальной амплитудой аудио: `AnalyserNode` в существующем графе воспроизведения (`playbackContext` в `apps/web/src/features/voice/services/voiceWs.service.ts`; для LiveKit — аналог на remote audio). При отсутствии аудио (demo, текст) — детерминированный ритм 140–180 мс.
- Амплитуда сглаживается (attack ≤ 40 мс, release ≤ 120 мс), чтобы рот не «дрожал».

### 8.3. Реакции (иммерсивность)

- Barge-in / `INTERRUPTED` → `surprised` с вздрагиванием (TTL 600–900 мс), затем `attentive`.
- Финальная ASR-гипотеза (`listening`) → короткий кивок 3–4°.
- `HUMAN_HANDOFF` → кивок и плавное смещение куба в сторону, «уступая место» человеку.
- `degraded` → оседание и затухание движения (§6, `sad`).
- Смена реплики в транскрипте → микро-реакция 2–3 px (SHOULD).

### 8.4. Переходы и ограничения

- Переход эмоций: spring 180–260 мс; подскоки/прыжки сопровождаются squash&stretch (сжатие ≤ 8%).
- **MF-13 MUST** — не более трёх одновременных анимаций; движение никогда не является единственным носителем информации.
- **MF-14 MUST** — при `prefers-reduced-motion: reduce` куб остаётся различимым в статике: эмоции кодируются формой рта и позой; lipsync заменяется статичной формой рта.
- Анимации — только `transform`/`opacity` (без layout thrash).

## 9. Эмоциональная озвучка (TTS)

### 9.1. Принцип единого источника

- **MF-15 MUST** — лицо и голос управляются одним источником эмоции: маппингом состояний (§4) или override (§5). Противоположные комбинации запрещены: `joyful`-куб не может звучать уныло, `sad`-куб — бодро.
- Если адаптер озвучки не умеет эмоцию, он обязан деградировать честно (NFR-10): нейтральная просодия без заявлений об эмоциональности. Куб при этом показывает эмоцию состояния, а голос звучит нейтрально; такая пара допускается только как явно объявленная деградация, а не как штатный режим (см. MF-21).

### 9.2. Контракт

```python
# speech/contracts.py — расширение TTSRequest (требует правки SSOT §5.7/§9 + ADR)
class TTSRequest(BaseModel):
    ...
    emotion: TTSEmotion | None = None   # {label: MascotExpression, intensity: 0..1}

# speech/tts/*: таблица возможностей адаптера
#   chatterbox:  exaggeration/cfg_weight  — нативно (реальные поля speech/tts/chatterbox_tts.py)
#   silero:      нет нативной эмоции      — нейтральная подача (опц. лёгкая просодия после бенчмарка)
#   kokoro:      нет нативной эмоции      — нейтральная подача (просодия детерминирована стилем)
#   mock:        игнорирует эмоцию
```

- **MF-16 MUST** — эмоция выбирается локально до синтеза: никаких дополнительных сетевых вызовов и подгрузок моделей на запрос; бюджет §2.6/§5.8 не расширяется. Исключение — плановая перезагрузка движка по MF-31.
- **MF-17 MUST** — таблица возможностей адаптеров зафиксирована в коде; отсутствие поддержки — не ошибка, а объявленная деградация.
- **MF-30 MUST** — параметры эмоции (`exaggeration`, `cfg_weight`, темп, высота, энергия) передаются в каждый вызов синтеза через `TTSRequest.emotion`. Изменение публичного `adapter.config` между синтезами запрещено: это общее состояние, оно небезопасно при параллельных ходах (barge-in, несколько сессий) и не покрывается тестами.
- **MF-31 MUST** — Chatterbox перезагружается планово: после каждых N генераций (N — параметр конфигурации, стартовое значение 4). Перезагрузка выполняется между синтезами, не прерывает идущий ход и не попадает в путь первого чанка текущей реплики. Её стоимость измеряется в MF-36 и не должна ухудшать first-chunk latency сверх согласованного порога.
- **MF-32 MUST** — тексты в TTS проходят предобработку ударений (`RuAccentStressPreprocessor`) до движка; в UI и в метриках уходит исходный текст (§5.7).

### 9.3. Таблица «эмоция → просодия»

**Единицы (MF-33):** высота тона — относительное изменение базовой f0 диктора в процентах (`+4%` = f0 × 1.04, около +0.7 полутона). Темп — множитель длительности. Энергия — качественная шкала, переводится в усиление не более ±2 дБ относительно нейтрали.

- **MF-18 MUST** — интенсивность эмоции масштабирует отклонения просодии (например, `intensity=0.3` даёт треть амплитуды от табличных значений).
- **MF-19 MUST** — `angry` не озвучивается в адрес клиента (policy-off, §6).

Требования к просодической постобработке (по результатам лабораторного прогона):

- **MF-34 MUST** — просодическая постобработка выполняется formant-preserving фильтром (ffmpeg `rubberband`, formant=preserved). Фолбэк на librosa (phase vocoder) в рантайме запрещён: в лабораторном прогоне он давал MOS ~1.0–1.3 против ~2.5–2.8 у rubberband, то есть делал звук непригодным. Если `rubberband` недоступен, просодия отключается, синтез идёт нейтрально, событие фиксируется в логе и в статусе озвучки (NFR-10). Тот же порядок действует при ошибке фильтра;
- для Chatterbox русская озвучка требует предустановки ударений (MF-32). Референсный клип тембра допускается только по MF-38;
- модель Chatterbox деградирует на длинных сериях генераций (resemble-ai/chatterbox #360); способ борьбы — MF-31.

Внешние зависимости (вносятся только после согласования, §9.5): ffmpeg с `rubberband` (системный бинарник), `ruaccent` (MIT, уже используется стеком Kokoro). Новых Python-пакетов сверх перечисленных в спеке не добавляется (MF-10 распространяется на Python).

### 9.4. Приёмка озвучки

- **MF-20 MUST** — A/B через `scripts/tts_ab_eval.py` (существующий инструмент): first-chunk latency не хуже baseline; WER round-trip не растёт выше согласованного порога (начальное предложение — ≤ +5% относительного WER); слепое прослушивание синтетических фраз на каждую достижимую эмоцию.
- **MF-21 MUST** — тест согласованности: для каждого достижимого состояния эмоция лица и директива TTS совпадают; контрастные пары (`joyful`+низкая энергия и т. п.) отклоняются.
- **MF-35 MUST** — объективные пороги на одном и том же наборе фраз (стартовые, уточняются после первого прогона):
  - UTMOSv2 нейтрального голоса ≥ 3.2;
  - UTMOSv2 любой эмоции ≥ 2.5 и не ниже нейтрали более чем на 1.0;
  - направление просодии: `joyful`, `surprised` — медианная f0 выше `neutral`; `sad`, `apologetic`, `empathetic` — ниже; проверка по медиане f0 и RMS на одной фразе;
  - слепое прослушивание: эмоция, распознанная слушателями, совпадает с заданной не менее чем в 2/3 случаев; размер выборки слушателей согласуется владельцем продукта.
- **MF-36 MUST** — метрики из MF-20 и стоимость перезагрузки MF-31 измеряются в одном прогоне: first-chunk latency до и после перезагрузки, WER round-trip ≤ +5% относительно baseline.
- **MF-37 MUST** — тест деградации: на серии из 12 генераций подряд UTMOSv2 нейтрального голоса не падает более чем на 0.3 относительно первой генерации при включённой политике MF-31.

### 9.5. Голос и референс

- **MF-38 MUST** — референсный клип тембра (`audio_prompt_path`) допускается только как синтетический, сгенерированный движком проекта из разрешённого голоса (стартово — Silero MIT `ru_ekaterina`). Запись реального человека и клип из внешних источников запрещены. Выбор референса фиксируется в конфигурации тенанта с указанием источника.
- **MF-39 MUST** — голос на тенант выбирается из реестра разрешённых голосов с указанием движка и лицензии. Стартовый кандидат для Silero — `ru_alexandr` (MOS 3.29 в лабораторном прогоне; `ru_bogdan` — около 3.17–3.19, в разных прогонах отличается). Выбор голоса не меняет контракт эмоций.
- **MF-40 SHOULD** — выходы Chatterbox содержат водяной знак PerTh. Это свойство движка фиксируется в документации тенанта; его допустимость для B2B — решение владельца продукта (§15).

## 11. Приватность и безопасность

- Куб отображает локально вычисленную эмоцию; эмоции и состояния не отправляются на backend как данные о человеке и не попадают в метрики (NFR-03, FR-12).
- Эмоциональная директива TTS — параметр генерации, не PII; хранение метки эмоции в `tts_events` (§8.3) — только label/intensity без аудио и текста (SHOULD, требует правки SSOT).
- В мимике и aria-метках запрещены PII, текст реплик, номера, имена, intent, цитаты источников.
- При появлении драйвера B (SER) классификация эмоции — чувствительный атрибут: решения по §7 SSOT и ADR обязательны; в этой версии таких данных не существует по построению.

## 15. Открытые вопросы

1. `chat_handoff` и `human_handoff` из §8.1 отсутствуют в TS-типе `VoiceState` — нужна ли отдельная задача на приведение типа к спеке (вне этой спеки).
2. Источник драйвера B (SER/sentiment) — отдельная спека + ADR.
3. Нужен ли тенанту переключатель эмоциональной озвучки (например, «эмоциональный голос вкл/выкл») в настройках §8.2 — решение владельца продукта; в этой версии политика только для `angry`.
4. Для `silero`/`kokoro` просодическая постобработка — решать после бенчмарка разборчивости; до этого нейтральная подача.
5. Допустим ли синтетический референс тембра (MF-38) для B2B-тенантов — решение владельца продукта и юриста.
6. Допустим ли водяной знак PerTh в выходах Chatterbox (MF-40) — решение владельца продукта.
7. Сила эмоции «радость» (`exaggeration` 0.55, высота +4%) и «удивление» — подтверждается слепым прослушиванием (MF-35); стартовые значения можно менять только по результатам прогона.
8. Размер выборки слушателей для слепого прослушивания (MF-35) и N для перезагрузки (MF-31) — согласуются владельцем, по умолчанию 4.
