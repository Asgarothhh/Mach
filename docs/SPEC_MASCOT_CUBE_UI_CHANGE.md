# Спецификация изменения: маскот-куб на экране разговора (`/voice/live`)

**Статус:** черновик для согласования (frontend/UI)
**Дата:** 14 октября 2026 г.
**Базовый документ:** `docs/SPEC_MASCOT_FACE.md` v0.2 (форма, атлас 14 эмоций, драйверы A/B, lipsync, TTS-директива). Здесь описано только то, что меняется в интерфейсе. Требования v0.2, которые не упомянуты ниже, действуют без изменений.
**Концепт (визуал):** `ui-anti-slop-concept.pdf` и `mockup_voice_live.png` (см. раздел 9).

---

## 1. Цель

Заменить волну `<Waveform variant="stage" />` на экране `ConversationPage` в блоке `.voice-stage` на маскот-куб. Куб показывает состояние сессии мимикой (форма рта) и позой корпуса. Текст состояния остаётся.

Изменение не добавляет новых данных, событий, сетевых запросов и зависимостей.

## 2. Что не меняется

- Форма маскота: скруглённый куб, рот — единственная лицевая деталь. Глаз и бровей нет (v0.2 §1, §7).
- Атлас из 14 выражений и таблица движений (v0.2 §6, §8).
- Маппинг состояний `VoiceState` → выражение (v0.2 §4.1). Значения не меняются.
- Тексты состояний в `stateCopy` (`ConversationPage.tsx`) не меняются (MF-23).
- Приватность: куб не отправляет и не логирует эмоции (MF-11, §11 v0.2).
- Демо-маркировка и разделение тестового голосового канала и телефонии.

## 3. Что меняется

| Место | Было | Станет |
|---|---|---|
| `ConversationPage.tsx`, блок `.voice-stage` | `<Waveform variant="stage" animated=... />` | `<MascotCube expression={...} />` |
| `Waveform.tsx` | используется на `ConversationPage`, `HomePage`, `ConnectingPage` | сохраняется; на `ConversationPage` больше не используется (v0.2 §7) |
| Декор стадии | фон `--color-stage`, огромный отступ сверху | фон `--color-stage`, заголовок и куб разнесены по вертикали, куб не перекрывает заголовок |
| Размер | — | `clamp(112px, 20vw, 168px)` (v0.2 §7) |
| Палитра | `--color-brand` на волне | `--color-brand` на корпусе, белый рот; тенант переопределяет `--mascot-body` |

Заголовок `voice-stage h1`, подпись `<p>` и `StatusBadge` остаются на своих местах. Куб размещается между заголовком и подписью.

## 4. Новые файлы

Пути из v0.2 §5.1 и §7 сохраняются:

- `apps/web/src/features/voice/components/MascotCube.tsx` — компонент, inline SVG, без библиотек анимации.
- `apps/web/src/features/voice/model/voiceExpression.ts` — функция `mascotExpressionForState(state: VoiceState): MascotExpression`.
- В `apps/web/src/styles/global.css` — секция `/* Voice mascot cube */`.

Тип `MascotExpression` и `MascotCubeProps` — как в v0.2 §5.1 (`expression`, опционально `intensity` по умолчанию 0.6).

## 5. Поведение

### 5.1. Маппинг (исчерпывающий)

`Record<VoiceState, MascotExpression>` без `default`. Ниже — значения из v0.2 §4.1 с учётом текущих состояний `ConversationPage`:

| `VoiceState` | Выражение | Поза (пример) |
|---|---|---|
| `idle` | `neutral` | парение ±3 px |
| `requesting_microphone` | `curious` | наклон 8° |
| `connecting` | `thinking` | медленный наклон 10° |
| `listening` | `attentive` | наклон вперёд, scale 1.03 |
| `processing` | `thinking` | покачивание |
| `speaking` | `speaking` | рот по амплитуде (lipsync) |
| `degraded` | `sad` | оседание, −10% яркости |
| `ended` | `joyful` | подскок 6 px, +10% яркости |

Демо-режим (`env.demoMode`) использует тот же маппер (MF-03). Отдельной демо-мимики нет.

### 5.2. Lipsync

- Для `speaking` при наличии аудио рот следует за амплитудой (`AnalyserNode` в playback-графе, MF-12). Атака ≤ 40 мс, спад ≤ 120 мс.
- В демо и при отсутствии аудио — детерминированный ритм 140–180 мс.
- Пока аудио-граф не подключён, допустим статичный рот `open` без анимации. Это отмечено как открытый пункт в разделе 10.

### 5.3. Override (задел)

Драйвер B (`expressionOverride`) в этом изменении не реализуется. Контракт и TTL — как в v0.2 §5.2. Эмоции B (`confused`, `skeptical`, `empathetic`, `apologetic`, `relieved`, `angry`) в MVP не выдаются (MF-07), `angry` отключена политикой (MF-08).

### 5.4. Движение и доступность

- Анимации только `transform` и `opacity` (v0.2 §8.4).
- Не более трёх одновременных анимаций (MF-13).
- При `prefers-reduced-motion: reduce` переходы мгновенные. Выражение различимо в статике: форма рта и поза (MF-14).
- `role="img"` и `aria-label` из таблицы v0.2 §10 (MF-22). Текст состояния на экране не дублируется дословно (MF-23).

## 6. Изменения в `ConversationPage.tsx`

Минимальная правка, без переписывания страницы:

1. Заменить импорт `Waveform` на `MascotCube` и `mascotExpressionForState`. `Waveform` на странице больше не используется.
2. В `.voice-stage` заменить строку с `<Waveform variant="stage" animated={...} />` на `<MascotCube expression={mascotExpressionForState(state)} />`.
3. Выражение вычисляется из того же `state`, который уже есть в компоненте. Новый state не вводится.
4. Остальная разметка (бейджи, кнопки, панели ответа, источников и диалога) не меняется.

## 7. Тесты (MF-25..MF-29)

- `apps/web/tests/frontend-contracts.test.mjs`, в стиле существующих тестов:
  - маппинг покрывает все значения `VoiceState`;
  - в атласе ровно 14 выражений;
  - `ConversationPage` импортирует и использует `MascotCube`;
  - в `MascotCube.tsx` нет `fetch`, `XMLHttpRequest`, `localStorage`, `sessionStorage`, `console.`.
- Команды проекта (из `apps/web`): `npm run check` (это `npm run test && npm run typecheck && npm run build`). Результаты фиксировать как фактические.
- Ручной чек-лист в demo: `idle` → `connecting` → `listening` → `processing` → `speaking` → `ended`; текстовый `degraded`.
- Визуальная приёмка 14 выражений через demo-предпросмотр (MF-28). `angry` — только в предпросмотре.

## 8. Зависимости и ограничения

- Новых npm-зависимостей нет (MF-10). `package.json` не меняется.
- Изменения backend, WebSocket-контрактов и БД нет.
- Тенант может переопределить `--mascot-body`. Геометрия не меняется.
- Логотип МТС не используется как корпус маскота (persona-бриф: нужна проверка брендбуком).

## 10. Открытые вопросы

1. Цвет корпуса: `--color-brand` (#ed0010) из текущих токенов или отдельный HEX от бренд-команды. Сейчас используется токен.
2. Lipsync: подключать `AnalyserNode` к `playbackContext` (`voiceWs.service.ts`) в этом изменении или следующим этапом (v0.2 §13, этап 2).
3. Персона-бриф (`/tmp/opencode/mts-belarus-mascot-persona.md`) описывает другого персонажа (яйцо, глаза, брови). Это расходится с v0.2 и с этим изменением. Решено: используется куб по v0.2. Если персонаж меняется, сначала нужна правка v0.2.
4. Тенантная настройка эмоциональной озвучки (v0.2 §15, пункт 3) остаётся открытой.
