# План разработки MTS Voice Agent: распределение задач между четырьмя разработчиками

Версия: 1.0\
Дата: 2026-10-11\
Единый источник требований: `SPEC_MTS_VOICE_AGENT.md`

## 0. Правила работы

Этот документ распределяет задачи, но не заменяет основную спецификацию.
При конфликте требований приоритет имеет `SPEC_MTS_VOICE_AGENT.md`
(SSOT). Ссылки ниже указывают на разделы SSOT. Перед изменением API,
схем событий, безопасности или архитектуры сначала согласовать изменение
SSOT.

-   [ ] Прочитать указанные разделы SSOT перед началом задачи.
-   [ ] Контракты API и доменных модулей сверять с разделами 9 и 14.
-   [ ] Не коммитить ключи, реальные транскрипты, телефоны или другие
    клиентские данные.
-   [ ] Для моделей фиксировать версии, лицензии, параметры запуска и
    benchmark.
-   [ ] Каждый PR включает тесты, инструкцию запуска и оценку влияния на
    latency/security.
-   [ ] 300--400 мс --- целевой показатель для оптимизированного
    сценария/этапа, не гарантия полного ответа при внешнем OpenRouter.

## 1. Распределение ответственности

  --------------------------------------------------------------------------
  Роль                    Основная ответственность   Модули
  ----------------------- -------------------------- -----------------------
  ML                      VAD, streaming ASR/TTS,    `speech/`, ML
                          речевые метрики и          evaluation
                          benchmark                  

  ML + Backend            Источники МТС, ingestion,  `rag/`, `knowledge/`
                          RAG, retrieval/reranking,  
                          grounding                  

  Backend + ML-Flow       API, orchestrator, state   `api/`,
                          machine, OpenRouter,       `orchestrator/`,
                          guardrails, persistence,   `security/`, `infra/`
                          аудит,                     
                          deployment/observability   

  Frontend                Голосовое веб-приложение и `web/`
                          админ-панель               
  --------------------------------------------------------------------------

Границы: ML не реализует бизнес-оркестрацию и не обращается напрямую к
PostgreSQL. ML + Backend владеет базой знаний, но не общей авторизацией.
Backend + ML-Flow владеет API/событиями и безопасным сквозным потоком.
Frontend использует только публичные API/WebSocket-контракты; браузер
никогда не получает ключ OpenRouter и credentials внутренних сервисов.

## 2. Очерёдность этапов

### Этап 0 --- каркас и контракты

SSOT: §§ 9, 13, 14, 15 «Этап 0», 16.

-   [ ] **Backend + ML-Flow:** репозиторий, конфигурация, Docker
    Compose, health endpoints.
-   [ ] **Backend + ML-Flow:** версионируемые Pydantic-модели API,
    WebSocket-событий и доменных сущностей.
-   [ ] **ML:** контракты VAD/ASR/TTS и формат partial/final
    результатов.
-   [ ] **ML + Backend:** контракты ingestion и
    `retrieve(query, filters, top_k)`, формат source metadata.
-   [ ] **Frontend:** каркас UI и подключение к тестовому WebSocket.
-   [ ] **Все:** текстовый E2E: запрос → retrieval → ответ с источниками
    → логирование → UI.
-   [ ] **Все:** `.env.example` без секретов, README, CI с lint/type
    check/unit tests.

Критерий выхода: каждый модуль запускается отдельно; mock E2E проходит;
health checks работают; секретов в репозитории нет.

### Этап 1 --- минимальный голосовой каскад

SSOT: §§ 5, 9--11, 15 «Этап 1».

-   [ ] ML: streaming VAD/ASR/TTS.
-   [ ] Backend + ML-Flow: оркестрация сессии, turn state, cancellation.
-   [ ] ML + Backend: подключаемый retrieval stub или минимальный
    индекс.
-   [ ] Frontend: микрофон, состояния разговора, partial transcript,
    воспроизведение и barge-in.
-   [ ] Все: E2E от микрофона до аудиоответа; пользователь может
    перебить бота.

### Этап 2 --- RAG, grounding и безопасность

SSOT: §§ 6--7, 11, 15 «Этап 2--3».

-   [ ] ML + Backend: ingestion и hybrid retrieval.
-   [ ] Backend + ML-Flow: подключить RAG и guardrails к потоку ответа.
-   [ ] ML: измерить влияние ASR-ошибок на retrieval.
-   [ ] Frontend: показывать источники и отсутствие подтверждения.
-   [ ] Все: тест на актуальные публичные источники; при недостатке
    evidence бот не выдумывает условия.

### Этап 3 --- админка, качество и демонстрация

SSOT: §§ 7--8, 11--12, 15 «Этап 4--5», 16.

-   [ ] Backend + ML-Flow: аудит, RBAC, retention, мониторинг и
    административные API.
-   [ ] Frontend: список сессий, транскрипты, источники, latency
    breakdown, состояние ingestion.
-   [ ] ML и ML + Backend: evaluation datasets и regression checks.
-   [ ] Все: нагрузочные, security и E2E тесты.
