# Project Instructions

## Architecture
- Document the actual project architecture.
- Follow existing module boundaries and dependency conventions.
- Inspect existing implementations before introducing abstractions.

## Development
- Keep changes focused on the requested task.
- Preserve existing functionality and backward compatibility.
- Do not invent APIs, dependencies, or environment variables.
- Document important design deviations.

## Testing
- Use the actual project test commands.
- Add tests for new behavior and bug fixes.
- Report executed commands and actual outcomes.
- Never hide failing tests.

## Security
- Do not expose secrets or sensitive information.
- Validate untrusted inputs.
- Follow the project's authorization and data-handling rules.

## Git and operations
- Do not commit, push, or deploy without approval.
- Do not perform destructive operations without approval.
- Do not modify unrelated files.
